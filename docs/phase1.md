# Phase 1: one renderer, a drafting dashboard, and a design refresh

Follows [phase0-decision.md](phase0-decision.md) (NARROW). Twilda is the static, git-native, no-database editor for prepared-section Astro sites, usable from a phone. This phase does the first four things that decision asked for. It does not build a GitHub App.

## 1. One renderer

Before this phase there were two renderers that disagreed: the site template in `src/render/document.ts`, and a preview renderer in `@twilda/core` (a generic `<main>`, no masthead, no `safeMedia`, a different `escapeHtml`). The desk's "proof" was a third, hand-written React view.

Now there is one: `renderDocument` in `packages/core/src/render.ts`. The site, the click-to-edit prototype, the demo editor's preview, the `examples/studio` preview, and the desk's page view all call it.

| Piece | Where |
| --- | --- |
| `renderDocument(doc, { annotate, chrome, dataFiles })` | `@twilda/core` |
| `renderPreviewPage` (a full HTML page, template CSS inlined) | `@twilda/core` |
| `escapeHtml`, `safeHref`, `safeMedia` | `@twilda/core` (one escaping rule: `& < > " '`) |
| `SiteChrome`, `DEFAULT_CHROME` (masthead, nav, colophon) | `@twilda/core`. The default is the Field Desk chrome. |
| `loadContentTree` (`node:fs`, `node:path`) | `@twilda/core/node` only |
| The template stylesheet | `@twilda/core/magazine.css` (canonical). `magazine-css.ts` is generated from it by `npm run sync:css`, and a test fails if they drift. |
| Click-on-the-page editing and the dotted-path rules | `@twilda/core/edit` and `@twilda/core/edit.css`. Browser only. The Astro site never imports it. |

The package root now bundles for a browser with no `node:*` imports. `tests/renderer-parity.test.ts` bundles it with esbuild for `platform: "browser"` and runs it in a bare `vm` context to prove that.

`annotate` adds `data-twilda-ref` (a dotted JSON path), `data-twilda-type` (`text`, `multiline`, or `image`) and `data-twilda-alt-ref`. It is off by default, so production HTML has no editing hooks. Article blocks are annotated too, not just pages.

### Parity result

- `npm run build` output (`dist/`) is byte-identical to the build from `main` before this change (`diff -r` is empty, including the hashed CSS file name).
- `tests/fixtures/renderer-golden/*.html` holds 20 golden files generated by the old site renderer from the demo content plus hostile fixtures (script tags, `javascript:` and `//` links, `'` and `"` in text, `data:` and `https:` images). The new renderer reproduces all of them byte for byte.
- Annotation invariants: every `data-twilda-ref` resolves to a string in the document, and annotated output with the attributes removed equals the plain output.

### Intended differences (documented, not accidental)

1. `demo-dist/preview` (`examples/studio`) now uses the template markup, `magazine.css`, and a studio chrome, and shows chart data tables from `dataFiles`. Before, it used the simple preview markup.
2. `renderPreviewPage` and the demo editor's preview use the template, not the old simple preview.
3. The shared `escapeHtml` escapes `'` everywhere. The old core one did not.
4. `renderDocument` from `@twilda/core` returns `<div class="magazine">` template markup, not `<main>`.
5. `loadContentTree` is no longer exported from `@twilda/core`. Import it from `@twilda/core/node`. `@twilda/astro` already does.
6. Core `renderDocument` now applies the site's `safeMedia` rule: an image whose path is not `/media/<a-z0-9->.svg` prints a "Plate unavailable" block, as the site always did.

## 2. Design refresh

`packages/editor/src/styles.css` was rewritten. White surfaces on a cool grey ground, rounded cards and pills, one violet accent, Public Sans for the interface. The reading surface keeps the magazine's own type, because it is the real template.

Phone (390px): a slim top bar with the draft's status, one scrolling column, and a bottom tab bar (Drafts, Page, Blocks, Export, Media) under a Save draft / Publish / Revert bar. Dialogs are bottom sheets.

Desktop (960px and up): the draft list on the left and the page in the middle. Blocks, Export, and Media open in a right-hand panel on demand, so the page stays wide enough to look like the site.

Screenshots are in `docs/screenshots/` (`phase1-*-390.png` and `phase1-*-desktop.png`).

## 3. Article-shaped drafting dashboard

- **Dashboard.** Every draft is a card with its kind, kicker, title, dek, a status pill, open `[VERIFY]` notes, and last edited. Status is `Draft · Not published`, `Unpublished changes` (a published copy exists and the draft differs), or `Published`. Filters (All, Drafts, Changed, Published) and a search box.
- **New draft from a template.** Blank article, Feature story, Data story, Short note, Front page, Topic page. A template is an ordered list of prepared blocks or sections with placeholder copy that already passes the `@twilda/core` schema, so it renders straight away. Nothing about this is a canvas: the parts are the same prepared types the Blocks panel adds, removes, and reorders.
- **The page is the draft.** The Page view renders the draft through `renderDocument` and edits it in place with the Phase 0 overlay (`mountOverlay`): tap text to edit it where it sits, tap an image to pick a plate, one field at a time, each checked against the schema. A refused value is turned back and says why. `[VERIFY ...]` notes are highlighted. Outlines show which parts are editable (on by default on touch screens).
- **Form and page stay in sync.** The Blocks panel edits the same document: add, remove, and reorder blocks or sections, and fields the page does not show.
- **Drafts save locally, instantly.** Edits are written to the device 250 ms after the last change (IndexedDB, then localStorage). Save draft is still there as an explicit action.
- **Publish is unchanged in shape.** Publish asks first, writes the published copy on this device, and if a GitHub token was pasted, also opens a pull request into `main` through `GitHubBackend` (branch `twilda/draft/<id>`, files `content/<id>/draft.json` and `published.json` since Phase 2). Merging that pull request is the publish decision.

The desk reads plates from the repo's `public/media` through a desk-only Vite plugin (`packages/editor/vite.config.ts`): a virtual module for the picker, the files served in dev and preview, and copied into the desk build. The Astro site and its `dist/` are not affected.

## 4. Auth and its limits

Token paste is the default and works with nothing deployed. The optional stateless proxy hook is kept. **No GitHub App is built**: that is the owner's decision (see Phase 0).

| Path | What it needs | Notes |
| --- | --- | --- |
| Paste a token (default) | A fine-grained personal access token for the repository with Contents: read and write and Pull requests: read and write. | Held in this tab's memory only. Not saved to storage and not in the repo. The Playwright test asserts it is not in `localStorage` or `sessionStorage`. Closing the tab forgets it. |
| Device flow (optional) | `PUBLIC_TWILDA_GITHUB_CLIENT_ID` (an OAuth App client id, public) and `PUBLIC_TWILDA_DEVICE_FLOW_PROXY` (a stateless pass-through to github.com's device endpoints). | github.com's device endpoints send no CORS headers, so a browser cannot call them directly. The button appears only when both variables are set. An OAuth App with `repo` scope is broader than a fine-grained token. For a public site repository, set the proxy's `scope` to `public_repo` ([how](../examples/device-flow-proxy/README.md#choosing-a-scope)). |
| No token | Nothing. | Publishing stays on this device. The desk says so. |

Scope limits to know about:

- The token can do what its scope allows. The desk only creates a branch, writes one file, and opens a pull request, but a stolen token is not limited to that. XSS in the desk page could read the token from memory. Use a fine-grained token limited to one repository and an expiry.
- Only people who can push to the repository can publish. There is no fork-and-pull-request path for people without push access.
- Phase 1 limit, lifted in Phase 2: the desk now checks whether `main` moved, merges silently when nothing overlaps, and shows a conflict sheet when it does ([phase2.md](phase2.md)).
- Images: the template only prints repo plates under `/media/<name>.svg`. `https:` images are still kept in the draft but show "Plate unavailable". Uploaded photos are shown from the device and committed to `public/media` in the pull request since Phase 2.
- Phase 1 limit, lifted in Phase 2: the desk and the click-to-edit page now share one layout, `content/<id>/draft.json` beside `published.json`.
- Not verified on a real iPhone or Android phone, or against real GitHub. Tests use WebKit with the iPhone 14 profile, Chromium, and a mocked GitHub API.

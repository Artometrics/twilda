# Changelog of rendered output

Changes to what a published page prints, recorded because the golden files in `tests/fixtures/renderer-golden/` pin that output byte for byte.

## External links in the older sections and blocks

**What changed.** Carousel slides, story and lead links, menu-shelf items, sources lists, downloads, embeds, and the chart data link used a site-path-only rule. An `https://` address, which the schema has always accepted, printed as `href="#"`. They now use the same rule as the newer sections: a site path or a validated absolute http(s) address (see `isWebUrl` in `packages/core/src/url.ts`). An external address prints as written with `rel="noopener noreferrer"`. A site path prints exactly as before. Everything else, including `javascript:`, `data:`, `//host`, credentials, spaces, quotes, backslashes, and punycode hosts, still prints `#`.

**Why.** A sources list that links nowhere is a bug, not a safety feature. The parity rule ("existing output stays byte-identical") protected sites that already existed; none outside this repository use Twilda yet, so it was lifted once instead of adding a setting.

**Golden files.** The 11 golden files whose content had an external link were regenerated by rendering the same corpus with the new renderer. The diff is anchors only (`href="#"` became the address, plus `rel`). Hostile fixtures still print `#`. Two tests guard this: a golden file may not link to `javascript:`, `data:` or `//`, and every external anchor in the golden files carries `rel="noopener noreferrer"`; `tests/render.test.ts` renders hostile targets with the schema bypassed and requires `#` for each.

**Also.** The browser-bundle parity test runs in a bare context that now provides `URL`, which every browser has and the link check needs; without it a link check fails closed and prints `#`.

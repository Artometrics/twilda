# AGENTS.md — Twilda CMS

Twilda CMS is a git-native static CMS for Astro. The public site is `src/` and builds with `astro build` (`output: "static"`). Content is JSON in `content/<id>/draft.json` and `published.json`, using the `@twilda/core` document contract. The visual editor is `editor/` and runs only in Vite dev. Do not import the editor from `src/`, and do not add an Astro adapter. Do not add an npm deploy script. Deploys are the GitHub Actions in `.github/workflows/firebase-deploy.yml`, `firebase-deploy-www.yml`, and `firebase-deploy-desk.yml`, and they run on merge to `main`.

The previous Expo novel workspace lived in this repo through commit `106b96f`. It is history. See `HISTORY.md`. Do not restore Expo, Supabase, or Netlify. Firebase Hosting for the static `dist/` is `firebase.json` and `.firebaserc` (project `twilda-510519`); the phone desk site id is `twilda-desk` and the marketing target `www` is site `twilda-landing`. Do not put secrets in those files.

## Commands

- `npm install`
- `npm run dev` — editor on port 5173, published site on port 4321
- `npm run typecheck`
- `npm test`
- `npm run build` then `npm run check:static`
- `npm run check:content`, `npm run check:secrets`, `npm run check:audit` — Phase 3 security checks (content and public-file audit, secret scan, `npm audit` against `security/audit-allowlist.json`). `npm test` includes the hostile-content suite in `tests/security/` and the header and built-output tests. See `docs/security.md`.
- `cd packages/editor && npm run test:e2e:csp` — the desk in a browser under the production CSP.
- `npm run starter:dev -- <corporate|magazine|leadgen>`, `npm run starter:build -- <mode>`, `npm run build:starters` — run a starter from `examples/starter-<mode>/`. `npm run starters:sync` rewrites them from the presets in `@twilda/core` (a test fails on drift). `npm run create:twilda -- <dir> --mode <mode>` scaffolds a project. `npm run test:e2e:starters` checks each at 320, 390, and 1280 px. See `docs/phase4.md`.
- `npm run build:edit` — Phase 0 click-to-edit target into `dist-edit/` (never deployed, never `dist/`). `npm run dev:edit` serves it on port 4322. `npm run test:e2e:edit` runs it at 390px and desktop. See `docs/phase0-click-edit.md`.

## Security rules

- Do not weaken a header or Content-Security-Policy in `firebase.json` or `EDIT_CSP`. `tests/csp.test.ts` pins them. No `unsafe-inline`, no `unsafe-eval`, no wildcard. A change that needs a new origin (for example a device-flow proxy) updates the test in the same pull request.
- The GitHub token stays in memory, goes only to `api.github.com`, and is never logged or stored. `tests/security/token.test.ts` enforces it.
- Link targets and media go through `packages/core/src/url.ts` and `media-guard.ts`. Do not add a second rule.
- Workflows keep a read-only token, no `pull_request_target`, and no secret in a step that runs pull-request code. `tests/security/workflows.test.ts` enforces it. See `SECURITY.md`.

## Product rules

- A site has a mode (`mode` in `content/site.json`: `corporate`, `magazine`, or `leadgen`; absent means magazine). A mode is a section library, theme tokens, and a default masthead from `packages/core/src/presets.ts`. It narrows what the desk offers and never limits what renders. Add a section type to `schema.ts`, `render.ts`, `library.ts`, `fields.ts`, and the presets together, with hostile-content tests. See `docs/choose-a-mode.md`.
- Starters in `examples/starter-*` are generated by `scripts/lib/starter.ts`. Edit the generator or the presets, then run `npm run starters:sync`. Do not hand-edit them. No npm publish.

- Saving a draft and publishing are separate.
- Sections and article blocks are prepared types from `packages/core/src/schema.ts` (`@twilda/core`). Add, remove, and reorder. Do not turn the desk into a freeform canvas.
- The static build reads published files only.
- Demo content stays fictional. Do not scrape a live magazine into `content/`. `drafts/artometrics/` is separate: real-fact DRAFT articles in our own words, each cited, with `[VERIFY]` notes for anything unconfirmed. It feeds the phone desk and is not read by the static build.
- No secrets in the tree. No `.env` required.
